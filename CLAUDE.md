# Portfolio Tracker — operating instructions for the agent

## What this is, before anything else

**A database. Not a decision maker.**

Three jobs, in order:

1. **Record what the owner decided** — faithfully, dated, in their own words.
2. **Read it back** — what they said, when, and what they wrote for themselves.
3. **Show the spread** — by theme, and by sector.

Advice is not one of them. Test any proposed feature, column or command
against those three: if it does none of them, it does not get built.

> **Note on this copy.** This is the public copy of a private project. The
> portfolio in it is generated by [`ops/seed_demo_book.py`](ops/seed_demo_book.py);
> see [README.md](README.md) for what is real here and what is not. The rules
> below are the real ones.

## How to talk to the owner

Assume no knowledge of git, hooks, or tooling. The audience is someone who
understands their own portfolio and not this codebase.

- **Short.** Two bullets asked for means exactly two.
- **Simple language, no jargon** — "runs automatically after I edit a file",
  not the name of the mechanism. The effect, not the machinery.
- A long, correct answer they cannot parse is worse than a short one.
- **Ask in choices, not essays.** Offer real options built from their own
  text, their own data, or a decision already made. An open "why do you own
  this?" is how the work stalls.
- **Preview then write.** Before any thesis, note, claim or comment is
  written, show the complete thing and wait for a yes. If one part changes,
  reprint the whole thing — they are confirming the artefact, not the diff.
- **Print every option for a fixed-vocabulary field.** Nobody recalls them,
  and a picker that truncates at four will hide the rest.

**Never ask "is this a bet, or a thought?"** That asks for introspection
about a distinction the code invented. Record what was said as a comment
FIRST, then ask once: *"want me to ask you about this later?"* Only a yes
makes it a bet. A bet is an upgrade, never a rival door.

**Three rules that protect real money:**

- **Never invent thesis content** — bear cases, catalysts, targets. `TODO` is
  the only acceptable fallback; a blank looks the same whether it was decided
  or forgotten.
- **Verify before claiming a position is held** — read `data/positions.csv`,
  never a journal file. Intent and execution diverge both ways.
- **Research is an input, never a directive.** It feeds the thinking; the
  decision belongs to the owner. Always surface the counter-argument.

## No number in prose that the code can compute

The most common defect this project has produced. Ten of sixteen row counts in
one document were wrong at the same time; a "24 of 70 notes written" line
appeared in three files while the real figure was different and the work was
finished.

**Name the command, never the number:**

```bash
venv/bin/python ops/counts.py       # every table, the writing queue, what is incomplete
```

## The commands

| | |
|---|---|
| [`/note`](.claude/skills/note/SKILL.md) | **writes what they think** — a thought, something someone said, a watch, a plan to buy or sell, or a full thesis. Takes a ticker, a **theme**, a **sector**, or `market`. Previews everything, writes only after confirmation, **all in one go** |
| [`/show`](.claude/skills/show/SKILL.md) | **reads** — what is owned, what was said, what is being watched, what is missing. Writes nothing, ever |
| [`/evidence`](.claude/skills/evidence/SKILL.md) | **files what they read** — a PDF, a chart, an article. Files the document **once** and attaches it to everything it bears on. **Stops before a claim:** a document is what was read, never what was decided |
| [`/level`](.claude/skills/level/SKILL.md) | **records what happened when a price was reached.** `breached_levels()` is not the whole answer — a hard stop that already filled leaves the position, so it appears in `orphaned_levels()` |
| [`/resolve`](.claude/skills/resolve/SKILL.md) | **records the verdict** when a bet reaches its check date |
| [`/review`](.claude/skills/review/SKILL.md) | **plain-English summary of what changed**, before any push |
| [`/market`](.claude/skills/market/SKILL.md) | **refreshes what the market says** — ETF breakdowns, holdings, vendor sectors. Asks before every write |

**Nothing in `claims.csv` can be edited to make a reminder go away.**
`check_date` is frozen and a recorded verdict can never be rewritten. An
overdue claim is resolved or it stays overdue.

## Where each record lives

Full detail — every column, every foreign key — is in
[docs/data-model.md](docs/data-model.md). What routes:

| Record | File |
|---|---|
| What a ticker means | `data/instruments.csv` — **the one place that says what a ticker means.** Every other table points at it by `instrument_id` |
| A live bet, or a watchlist item | `data/claims.csv`, `kind=claim` / `kind=watch` |
| **Which trade executed a decision** | `claims.trade_ids`, filled **after** the trade. The only join between what was planned and what was done |
| **A thought, or something someone said** | `data/commentary.csv` — `kind=thought` (theirs) or `commentary` (somebody else's). **The one store a row may LEAVE** — a comment is disposable and a bet is not |
| What a theme is | `data/clusters.csv`. **Summing every row over-counts** — a group carries its children's money. Run `clusters.weights()` and read the rows where `is_group` is False |
| A price that should make you act | `data/levels.csv`. `hard` = a real order at the broker and **requires `broker_verified`**; `soft` = an own trigger. Never edited — end the level, then add a new one |
| Why a bet was taken | `data/claim_setups.csv` — one row per reason, so a claim can be trendline AND macro |
| How big the bet was | `claims.nav_pct` — % of total account value including cash, computed at write time, never typed, frozen. It refuses to compute rather than size against a short denominator |
| Market state when the decision was made | `claims.atr`, `claims.sma_200` — point-in-time, never updated |
| Past trades, splits, expiries (facts) | `data/transactions.csv`, `data/corporate_actions.csv`, `data/option_events.csv` |
| Anything they read | three tables — `evidence.csv` (**one row per document, stored once**), `evidence_summaries.csv` (one write-up per theme), `evidence_links.csv` (what it is about; `page` and `why` sit on the **link**) |
| What an ETF is made of | `data/market/etf_compositions.csv` — normally fetched, not typed from memory; `source_quality` says which |
| What a sector means | `data/sectors.csv`. A label not in this table **raises** |
| What is still unwritten | `notes.status()` — ordered by money, a group then its themes then their holdings |
| Reasoning that cannot be a cell | `notes/positions/<TICKER>.md` — **must** have `## Bear case` and `## Catalysts` |
| A position they exited | `notes/positions/closed/<TICKER>.md`, and `instruments.set_status(id, "closed")` |
| A name being considered | `notes/positions/watchlist/<TICKER>.md` |
| Why a whole theme exists | `notes/clusters/<name>.md` — **must** have `## Why this cluster exists` and `## What would end it`. **Write the group before the themes inside it, and the theme before its holdings** |
| Machine output | `ops/` — never `notes/` |

**`hold` and `watch` state no trade**, so `claims.happened` stays blank rather
than False — without this a session reports a hold as a plan that was never
executed. `claims.why_not` is why a planned trade did not happen;
`still-waiting` is the value that earns the column, because without it patience
and forgetting look the same.

## The modules worth naming

```python
from src import instruments, claims, evidence
instruments.resolve("ASML_EUR")   # -> "ASML"   broker lot -> instrument
instruments.gaps()                # what is incomplete — visible, never blocking
instruments.price_warning()       # "" when prices are fresh

claims.add_claim(...)             # refuses an incomplete row
claims.link_trades("c0007", "1000000012")   # after the trade fills
claims.follow_through()           # was the written plan acted on? how many days later?
claims.scoreboard()               # hit rate by conviction, origin, setup, and call
clusters.weights()                # never sum the rows yourself
evidence.inherited("instrument", "ASML")    # never merged in, never stored:
                          # a report about technology is not research on ASML
```

- **One instrument, many broker lots.** `ASML_USD` and `ASML_EUR` are two rows
  in `positions.csv`, both `instrument_id=ASML`.
- **A new instrument needs only id, name and type.** Never let a missing sector
  stop a trade being recorded.
- **Prices carry `priced_at`.** Say when a price is stale rather than showing
  it as if fresh. `price_age_days()` reports the OLDEST lot, so one lot left
  behind makes the whole book read stale.
- **`currency` says what `cost_basis` and `last_price` are quoted in**;
  `market_value` is always the base currency.
- `add_claim()` **refuses** an incomplete row. If it cannot be completed, write
  prose in the note — never a half-filled row. History is immutable: only
  `outcome`, `resolved_date`, `resolution_note` and `why_not` get filled later.

**Live code:** `ls src/` is the list. Four worth naming because nothing else
does — [`commentary.py`](src/commentary.py) (the one store a row may leave),
[`holding.py`](src/holding.py) (everything about one holding, and what nothing
explains), [`notes.py`](src/notes.py) (note shape and the writing queue),
[`exposure.py`](src/exposure.py) (look-through sector exposure).

## Guards (they run themselves)

| Guard | Fires | Does |
|---|---|---|
| [`ops/hooks/pre-commit`](ops/hooks/pre-commit) | every `git commit` | blocks commits on `main`; validates every staged data table **from the index, not the working tree**; blocks history rewrites; rejects misnamed or oversized screenshots |
| [`claude-pretooluse.sh`](ops/hooks/claude-pretooluse.sh) | before `git push`/`commit` | asks for approval on a push; denies a commit on `main` |
| [`claude-posttooluse.sh`](ops/hooks/claude-posttooluse.sh) | after editing `.py` in `src/`/`tests/` | compares failures to `ops/test_baseline` |
| [`claude-sessionstart.sh`](ops/hooks/claude-sessionstart.sh) | every new session | names anything traded recently that no claim explains |
| [`claude-stop.sh`](ops/hooks/claude-stop.sh) | end of each turn | names claims now due, levels the price has reached, levels that **cannot** be checked, market data going stale, and uncommitted files |

**Getting work to GitHub — never commit to `main`, never merge.** Branch →
[`/review`](.claude/skills/review/SKILL.md) → push → pull request → the owner
clicks Merge. Full steps: [docs/github-workflow.md](docs/github-workflow.md).

## Broker data

```bash
venv/bin/python -m src.ibkr_sync            # --cached to re-parse, no fetch
venv/bin/python ops/data_gaps.py            # what the market data is still missing
venv/bin/python -m pytest tests/ -q         # must be green
```

**Never run `ops/refresh_market.py --write` directly.** It reaches the internet
and overwrites real sector and holdings data. That is
[`/market`](.claude/skills/market/SKILL.md)'s job — the only thing that
previews, asks, and then runs it.

**Read [docs/data-conventions.md](docs/data-conventions.md) before acting on
sync output.** Each file merges differently, `Added:` needs its instrument row
written by hand, and `Removed:` does **not** reliably mean "position closed".

**Real stop orders live at the broker, and no robot watches them.**
`levels.csv` `kind=hard` rows are the record of the ones the system has been
told about, with `broker_verified` saying when they were last confirmed. For
anything else, ask the owner to check the broker.

**The broker's re-fetch window is finite.** History older than it cannot be
re-fetched, so never drop a column or a section to tidy up.
`unreconciled_shares()` reports share counts that trades cannot explain.

## Sector vs theme — two different questions

`sector` is a standard sector label, comparable to a benchmark. `cluster_id` is
the owner's own theme. A theme legitimately spans sectors, and some holdings
are funds with no sector at all. That is correct: **never merge sector labels
to make a theme tidy.**

**Theme vs exposure.** `cluster_id` is *why it was bought* (intent);
`exposure.by_sector()` is *what you are exposed to* (fact). A technology fund
is a core holding by intent and mostly technology by fact. **Never make one
answer both**, and never write a weight into a note — run the function.

**There are no sector caps or theme targets.** Never quote a limit; ask.

**Say how much of an exposure answer is a guess.** `exposure.coverage()` names
which funds a number depends on and how old each breakdown is.

## Journal (`notes/`)

**For learning and noticing patterns, not a rules engine.** Observation
language, not rule language. Do not propose new commitments.

Layout and the two rules the commit hook enforces:
[notes/README.md](notes/README.md).

## Never commit

`.env`, raw broker exports (they carry the account number), paid research
PDFs, inbox folders, `*.pdf`, `*.xlsx`, `*.bak`. Filed screenshots **are**
committed: `YYYY-MM-DD-TICKER-subject.png`, size-capped — the guard enforces
it. **Never paste a key into chat; if one is pasted, say so** — it needs
rotating at the provider, and no guard can catch that one.

## Code conventions

Type hints; docstrings explain *why*. Pure functions, file IO at the edges.
Tests required for new analytics — **no test is ever weakened to go green**.
One commit per logical change with the "why".

Design history, with the reasoning kept:
[_archive/design-record.md](_archive/design-record.md), and the specs linked
from [README.md](README.md).
